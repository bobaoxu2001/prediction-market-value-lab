**Prediction Market Value Lab — project review, 8 September 2026**

The project builds and its existing tests pass, but the review found defects that can change settlement labels, research inputs, reported performance, opportunity eligibility, and displayed fees. These need correction before treating the analytical results as reliable. The public web app and API are currently unavailable.

Reviewed local branch `measure-before-selling`, HEAD `f6c821b`, including the pre-existing modifications to `models.py` and the three untracked forecast-audit, rederivation, and migration files. Remote `main` was independently checked at `72d3e89d453bd2dc7e0347dc9cd4ab0af27dbd87`; the local checkout is 19 commits ahead of that revision. This report evaluates the local checkout, not a claim that its fixes have been deployed.

There are **17 prioritized findings** below. P1 means a correctness issue to fix before relying on the affected result. P2 means an actionable issue for the next repair cycle. Related defects are grouped where one user-visible capability is affected. Reproductions used temporary or in-memory data and mocked external services; no real orders, payments, collection jobs, or operational-data changes were made.

**Findings**

1. **[P1] Known-invalid forecasts can still enter research cohorts.** [Forecast selection](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/research/build.py:143>) ignores `research_eligible` and `validity_status`; it filters only station, target date, and availability. A temporary dataset with an older valid 85°F forecast and a newer ineligible `DEFECT_TARGET_DAY_SHIFT` 100°F forecast admitted the 100°F value, produced probability 1.0, and reported no exclusion. The current local database contains 3,102 such ineligible original rows; correction rows winning a timestamp tie does not enforce eligibility. Establish validity for new captures, filter before point-in-time selection, and make correction tie-breaking deterministic. This is especially relevant to the uncommitted validity work.

2. **[P1] Polymarket proposals can be recorded as final settlements.** [Resolution inference](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/providers/polymarket.py:541>) turns near-terminal prices into terminal payouts without requiring final resolution. A closed market with prices `[0.995, 0.005]` and UMA status `proposed` returned `resolved=True` and YES payout $1. The [settlement consumer](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/backtest/settlement.py:137>) grades these results and subsequently excludes already-settled markets from polling, so a later correction can be missed. Require authoritative finality and the actual payout; closure and indicative prices are insufficient. The official process explicitly separates proposals, challenges, and resolution. [Polymarket resolution documentation](https://docs.polymarket.com/concepts/resolution).

3. **[P1] Simulated exits can erase losses or invent fills.** In [the exit branch](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/alpha/simulator.py:377>), `_close()` returning `None` still releases exposure and deletes the position. Reproduction: 83 YES contracts entered at $0.30, no bid when the strategy exits, then a NO settlement; output was zero trades and zero remaining exposure, with no warning. Separately, [exit pricing](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/alpha/execution.py:434>) averages only the quantity available but discards that quantity; [the caller](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/alpha/simulator.py:599>) applies the price to the full position. With one contract bid at $0.45, it reported all 83 sold and +$9.56 while the remaining 82 should still face settlement. Preserve unfilled inventory and return actual filled quantity from execution.

4. **[P1] Backtest selection depends on future settlement availability.** [The backtest loader](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/backtest/engine.py:484>) uses `settled_only=True` before applying daily top-N selection. With rank 1 pending and rank 2 settled YES, the top-one strategy selected rank 2. After rank 1 settled NO, rerunning the same historical day instead selected rank 1 and reported −$10. Settlement availability therefore changes which trade supposedly occurred. Select from all eligible publications first and leave selected unresolved contracts pending.

5. **[P1] Five-day-old books can publish actionable value recommendations.** [Admission gates](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/value/ranking.py:362>) do not reject `stale_quote`. Freshness reduces the score but is not a hard exclusion. A candidate built from a five-day-old book carried `stale_quote`, passed the gates, and ranked; [publication](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/value/pipeline.py:410>) then initializes it as `STILL_ACTIONABLE`. Reject unusable target books before publication, including when they are the only available candidate.

6. **[P1] Rejected cross-market matches retain their old verified status.** [Match refresh](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/arbitrage/pipeline.py:150>) skips an incompatible verdict before updating the existing row. In-memory reproduction: matching Bitcoin $100,000 contracts first received an identical match with confidence 0.9800; changing one threshold to $120,000 made verification incompatible, yet the persisted match stayed identical. [Value scoring](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/value/pipeline.py:125>) continued supplying the other contract’s 0.80 quote as an independent prior. Persist invalidation for rejected matches and for old matches that no longer qualify for candidate generation.

7. **[P1] An empty arbitrage scan leaves the previous actionable batch visible.** [The API batch query](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/services/api/src/pmvl_api/routers/arbitrage.py:92>) selects the latest batch from opportunity rows. An empty successful scan writes no such row. An isolated API reproduction created one old executable opportunity, ran a new successful empty scan, then requested `/arbitrage?view=actionable`: the response still returned the old batch with `actionable_count=1`. Health metadata does not suppress it, and saved labels are not revalidated. Track scan batches independently of results and serve the latest completed batch even when its result count is zero.

8. **[P1] Both extension adapters can use the wrong fee terms.** [Polymarket parsing](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/apps/extension/src/venues.ts:257>) reads `market.fee` and defaults to zero, ignoring the current `feesEnabled` and `feeSchedule.rate` fields. A live fee-bearing Gamma market supplied rate 0.04 and no `fee`; an actual-source reproduction with rate 0.07 calculated $0 instead of $1.75 for 100 contracts at $0.50. [Kalshi parsing](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/apps/extension/src/venues.ts:147>) expects fee metadata on the market and never resolves series terms. Live series `KXMLBSPREAD` supplied multiplier 0.5 while its market omitted that field; the adapter calculated $1.75 instead of $0.88 for the same size and price. Fetch authoritative terms and distinguish missing information from a confirmed zero fee. Arithmetic conformance tests do not test these metadata adapters. Sources: [Polymarket fee migration](https://docs.polymarket.com/changelog/predictions), [fee formula](https://docs.polymarket.com/trading/fees), [Kalshi series schema](https://docs.kalshi.com/api-reference/market/get-series), [observed series](https://api.elections.kalshi.com/trade-api/v2/series/KXMLBSPREAD).

9. **[P2] Multi-outcome scans can call a basket executable when a leg rejects orders.** [The label gates](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/arbitrage/multi_outcome.py:123>) check freshness and liquidity but not each leg’s `accepting_orders`; the logical scanner has the same omission. Open status is independently insufficient. Two fresh $0.30 × 1,000 legs, with one marked `accepting_orders=False`, returned `EXECUTABLE` and $350.60 profit without a blocking flag. Apply the per-leg availability gate already used in the complete-set and cross-platform paths.

10. **[P2] Gross-only sizing can hide a profitable smaller arbitrage.** [Complete-set sizing](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/arbitrage/complete_set.py:51>) selects a large gross-profitable quantity before fees and slippage, then discards the result if that quantity is net-negative. With each ask ladder containing $0.30 × 100 followed by $0.49 × 9,900, the default scan returned no result; the same scan capped at 100 sets returned executable profit of $35.06. Search quantity using net economics so expensive marginal depth cannot conceal a profitable prefix.

11. **[P2] Resting maker orders can fill after their intended expiry.** [Pending-order processing](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/alpha/simulator.py:325>) attempts a fill before checking the review interval; expiration is checked only after a failed fill. With an order at time zero, a 30-minute interval, and the first eligible trade at +100 minutes, the actual simulator recorded a 73-contract fill at +100 minutes. Bound the trade window by expiry and expire the order before admitting later volume.

12. **[P2] NO-side cost explanations and share previews can show the opposite proposition.** [The cost narrative](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/apps/web/app/(research)/cost/[id]/page.tsx:337>) always says the event must occur at the break-even percentage. For NO costing $0.60, non-occurrence must reach 60%, equivalent to occurrence at most 40%. The local browser confirmed the defect on “Boston wins” with Buy NO selected. [The share image](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/apps/web/app/(research)/cost/[id]/opengraph-image.tsx:115>) independently fetches `side: "yes"`, ignores data mode, and does not label that side. Carry the selected side through explanation and preview, or use a neutral preview when that is not possible.

13. **[P2] Temporary Clerk failures acknowledge billing events without applying them.** [User lookup](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/apps/web/lib/auth-server.ts:131>) catches every exception and returns false; [webhook processing](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/apps/web/app/api/stripe/webhook/route.ts:180>) interprets that as a deleted user and successfully skips the event. The actual route with external services stubbed returned HTTP 200 `received=true, outcome=skipped` for a Clerk 503, without applying entitlement. A payment or cancellation may therefore lose its retry. Distinguish an authoritative not-found response from transient failures and return a retriable failure for the latter. Billing is currently disabled/test-only, limiting present exposure.

14. **[P2] The extension retains old-side prices while replacement data is pending.** [Reload handling](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/apps/extension/src/content.ts:159>) clears cached state only when the side is unknown. Switching from a known YES side to NO retains the YES book while requests are outstanding, and the rendering path can continue repricing it when size changes. An actual-source DOM reproduction showed `detectSide()=no` while the panel still displayed “Entry cost · YES” and its prices. Clear old contract/side state before awaiting replacement data and show a loading state; retain cached data only for refreshes of the same contract and side.

15. **[P2] Recreating the Docker worker loses the research archive and raw payloads.** [The worker service](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/docker-compose.yml:44>) has no persistent volume. [Research path resolution](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/services/worker/src/pmvl_worker/jobs.py:883>) uses the package’s default directory regardless of the PostgreSQL URL, putting the archive and payloads under `/app/data` in the container’s writable layer. Only PostgreSQL has a named volume. Container recreation therefore removes the time series and original payload bytes while database references survive. Persist the research directory explicitly and share its configured location with readers. This was verified from path resolution and Compose configuration, not by destroying a container.

16. **[P2] `/system?mode=live` returns incorrect provenance metadata.** [The system handler](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/services/api/src/pmvl_api/routers/system.py:102>) overwrites its `DataMode` parameter with a `DeploymentMode`, then passes that value into the response envelope. An isolated request returned `data_mode=local_development` plus a synthetic-demo warning despite requesting live data. The frontend envelope type expects `live`, `demo`, or `all`. Keep deployment mode separate and pass the original provenance mode to the envelope.

17. **[P2] Re-running rederivation reverses superseded lineage status.** In the untracked [rederivation routine](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/research/rederive.py:118>), classification overwrites the original’s status before [the already-corrected check](</Users/xuao/Documents/2025 找工作/AI Projects/prediction-market-value-lab/packages/market-normalization/src/pmvl_markets/research/rederive.py:135>). The first run marks it `SUPERSEDED_BY_RAW_REDERIVATION`; a second run changes it back to `DEFECT_TARGET_DAY_SHIFT` and skips further handling. The local database exhibits 3,102 corrections and 3,102 original rows in that defective rather than superseded state. Preserve or reapply the superseded status when the correction already exists; test repeat-run metadata as well as row counts.
